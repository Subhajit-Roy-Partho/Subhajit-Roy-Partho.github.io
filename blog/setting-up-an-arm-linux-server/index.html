Setting Up an ARM Linux Server

Distro choice, a lightweight desktop environment, and the NVML/CUDA fix needed for SLURM to see GPUs correctly on ARM (aarch64/sbsa).

#arm#linux#slurm#gpu

Important notes

  • The welcome banner lives at /etc/motd — ASCII art looks great there.
  • Distro choices, roughly in order of how much trouble they gave me:
    1. Debian
    2. Fedora
    3. Arch
    4. Ubuntu (can even damage firmware on some ARM boards)

Fixes

SLURM GPU segregation

SLURM uses NVML to detect and segregate GPUs during scheduling, and on my ARM setup this API wasn't working out of the box.

  1. Find the library: sudo find / -name "libnvidia-ml.so" — for me it was at /usr/local/cuda-12.2/targets/sbsa-linux/lib/stubs/libnvidia-ml.so.
  2. Copy it to /usr/lib.

  1. /usr/lib should already be in ldconfig's search path; if not, add it under /etc/ld.so.conf.d and run sudo ldconfig.
  2. Verify with a small NVML test program:

If it prints the correct GPU count, the fix worked.

Rebuilding the NVIDIA kernel module

Logs land in /var/cache/akmods/nvidia/{Kernel Version}. Check your kernel version with uname -srm.

Warning

Never point /usr/bin/gcc (or g++) at a different major version than the system default — it breaks core system files, including the NVIDIA driver akmod.
