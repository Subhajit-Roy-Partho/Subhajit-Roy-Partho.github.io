A basic operation that comes up often: extending the size of an LVM partition.

Check the current disk configuration with `fdisk -l`, `lsblk`, `vgs`, `pvs`. Changes should target the `/dev/mapper` entry — there's no need to touch `/dev/sd*` or `/dev/nvme*` directly.

```bash
lvextend --size 236G /dev/mapper/ubuntu--vg-ubuntu--lv
```

Then grow the filesystem to match:

```bash
resize2fs /dev/mapper/ubuntu--vg-ubuntu--lv
```

Verify with:

```bash
df -h
```

## Conclusion

LVM is a great tool if you want robust, if unglamorous, dynamic partition management. BTRFS is simpler to work with, but can cost more CPU than LVM+ext4 — which is why many people still prefer LVM for server systems.
